# subagent-driven-dev · 可复制模板

> 按需读：P0-3 `subagent-driven-dev` 管协作与所有权，P0-2 `model-routing` 管路由与替补顺序；本文件只放自包含任务与失败交接模板。
> 方括号替换为实际值。子代理看不到本会话，主 agent 必须自带完整任务信息，不让它自行读计划猜需求。

## 零、captain 指派前记录

本段由主 agent 保存，不整段复制给成员。只传成员完成任务所需的能力限制和任务上下文。

```text
任务与风险：[任务 ID / 类型 / 风险]
能力要求：[文本 / 图片、工具、上下文与输出规模、审查独立性]
数据边界：[公开 / 脱敏 / 私密及实际端点政策]
目标完整路由：[provider / 含斜杠的完整 model]
配置与本会话：[白名单允许、provider 启用、目录 / 政策是否已生效]
计费与授权：[免费声明 / 付费 / 套餐；用户授权范围]
effort：[已核对目标映射 / 未核实故省略]
兼容替补：[必要时按模型能力筛选，不空跑]
本轮已试路由与预检拒绝项：[共享三路由预算，不因换链清零]
运行时前提：[相关工具可用；若为宿主启动失败，不进入模型轮换]
```

## 一、subagent 自包含 prompt

```text
你正在执行任务 N：[任务名称]

## 任务描述
[原任务完整内容]

## 上下文与范围
工作目录：[绝对路径]
必要背景与依赖：[上下文]
允许修改：[路径与行为边界]
不得修改 / 非目标：[路径与行为边界]
交付物：[文件或结论]
验收标准：[逐条条件]
验证命令：[从项目实际推导的命令]

## 执行边界
当前路由由主 agent 指定：[完整 provider / model，仅供汇报]
不要自行换模型、遍历免费入口或再开子代理。
不清楚的需求 / 依赖先上报，不猜测。
严格执行指定任务；实现按要求遵守 TDD，运行验证并自审。
除非任务明确要求，不提交、推送、部署或重复外部写操作。

## 力不从心与失败
需要架构决策、缺少上下文、发现超范围重构时停止并上报。
入口限额 / 鉴权 / 参数错误单独上报错误证据，不伪称任务或测试通过。
失败前已有文件修改、外部操作、后台作业都必须列明。
主 agent 负责限额替补；你只交接，不启动新的执行者。

## 汇报格式
- 状态：DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
- 实际路由：[provider / model]
- 交付与文件定位：[路径、行号、结果]
- 验证：[命令、退出状态、结果；未执行写明原因]
- 剩余风险 / 自审发现：[内容]
- 若失败：[错误类型、最小脱敏证据、已完成工作、待停止作业]
```

## 二、限额替补交接 prompt

仅在旧执行已停止、相关后台作业已收集 / 停止、文件与外部副作用已核对后使用。替补使用普通 `subagent` 的完整 provider / model，不用无法覆盖路由的 `subagent_fork`。

```text
你正在接续任务 N：[任务名称]

## 原任务与验收
[保留原任务全文、工作目录、范围、交付物、非目标与验收标准]

## 路由切换记录
原路由：[完整 provider / model]
失败类型：[策略 / 鉴权 / 限额 / 上游可用性 / 输入或参数 / 宿主启动 / 质量失败]
最小失败证据：[错误码与脱敏信息、发生在模型启动前或后，不含密钥]
故障范围与冷却：[入口 / 账号 / 共享池 / 实际端点；恢复条件]
本轮已尝试的完整路由及预检拒绝项：[最多三个路由的共享预算不重置]
目标路由：[完整 provider / model；本会话已放行]
能力要求与替补依据：[输入模态、工具、容量和审查独立性仍满足]
计费与授权：[免费声明 / 付费 / 套餐；授权范围]
是否能力降级：[否 / 是及理由；任务要求必须仍可满足]

## 已有工作与恢复点
旧执行与关联作业：[已停止 / 已收集的证据]
已有文件改动与测试：[定位与结果]
已完成的外部操作：[请求、提交、产物或无]
需要继续：[未完成部分]
不得重复：[已产生副作用的操作]

先读现有成果，核对恢复点，再完成剩余工作；不要盲目重放原任务。
保持原验收，不自行换入口、不新建子代理。
按自包含任务模板汇报，并附实际路由、恢复点与验证证据。
```

> AgentTeams 的替补交接写入原任务的指导消息 / 新成员 executionPrompt，并通过 `reassign_task` 改 owner。保留任务 ID、DAG 和验收；替补成员只能使用新的 attempt_id。

## 三、两阶段审查输出

规格合规先过，再审代码质量；两阶段失败分别写明。只读实际产物，不用实现者报告代替证据。

```text
### 规格合规
[通过 / 不通过，逐项验收证据]
### 优点
### 问题
#### Critical（必须修复）
#### Important（应该修复）
#### Minor（可以改进）
### 评估：可以合并？[是 / 否 / 修复后]
### 实际审查路由与限制
[完整路由；未执行的验证、缺失上下文与剩余风险]
```
