# 委派与团队协作

> 保留技能名与既有引用。模型、入口与预算由 `model-routing` 维护；本文只管协作生命周期。新功能 / 行为变更先与用户确认设计。
> **派活前先问用户用哪个模型通道（官方 / tianxun / d1），不得自行默认。**

## 一、选形态

先按门槛判定，再选形态。**门槛看任务结构，不看用户是否说出「组队」**；用户只描述目标时自行判定。满足右列**任一**条件即命中该行：

| 形态 | 命中条件（任一） | 动作 |
|---|---|---|
| AgentTeams | ① ≥2 个可独立验收且可并行的子任务；② 需要 requirements → implementation → verification → review → integration 质量链；③ 需跨多轮盯长任务 / 中途汇报；④ 子任务需分批路由到不同模型 | `agent_teams_*`，默认暂存后批准 |
| 单点 `subagent` | 单个自包含子任务：无依赖、无质量门、无需并行 | 一次派完；依赖已完成会话上下文用 `subagent_fork` |
| 主 agent 自己做 | 单文件小改、紧密耦合、全局整合、改同一文件的多步 | 不委派，不为「免费」增加委派 |

- 边界不清时取**门槛更低的一档**（宁建队不硬扛），但只建**最小 DAG**：不凑人数、不拆无依赖的伪并行。
- 插件常驻提示词的「Mentioning, quoting, discussing, or declining AgentTeams alone is not a request to start work」只禁止把**讨论**当建队令，**不否决本表①②③④**。
- 并行任务不同时修改同一文件；多个独立单点可同条消息启动。
- 禁用 `spawn_teammate` / `team_task_*`。

## 二、不可省的门

1. **批准**：按需看已有团队，不重复创建。新团队默认 `approval="required"`，暂存时建完最小 DAG；展示后停下，创建 / 编辑当轮不得 approve。automatic 仅用户明确要求立即运行时使用。
2. **派活**：每任务有 `subject`、上下文、范围、非目标、交付与验收；`kind` / `assignee` 显式设置。前置全部完成才可领取；调度器启动就绪任务，不用消息催启动。
3. **所有权**：派活 / 重试用 `reassign_task`，先吊销旧 attempt 并等待静止。captain 不替成员 claim，成员每次更新带当前 `attempt_id`。活跃工作不手改契约或路由，错误契约走 `amend_task`。
4. **验收**：先规格合规、再代码质量；读实际产物与命令证据，不信自述。实现者不批准自己的实现，不能伪造通过或为换入口降低验收。全质量链含 integration；自动 repair / review 循环不重复造。
5. **暂停与收尾**：用户停止后 halted，后续明确要求才 resume。等待成员时结束本轮，不忙轮询。全部必需任务终态、成员 idle / ready 后汇报并归档；未完成工作不擅自丢弃，部署须另获批准。
6. **成员边界**：本机 `memberMaxDepth: 0`，成员不上嵌套子代理、不自行换模型；captain 执行替补。`.agent-teams/` 不手改；限额不授权 captain 接管实现 / 审查。
7. **指派前预检**：按 `model-routing` 核对白名单与本会话生效状态、任务能力、工具可用性、计费授权、effort 和三路由预算；配置允许不等于本会话已放行。团队模型启动前故障按协议一「预检与启动故障」处理，不能换遍模型。

## 三、单点与重派

- `subagent` prompt 自带任务全文、绝对工作路径、必要背景、允许 / 禁止改动、验收与汇报格式；力不从心停止上报。仅传必要上下文，不塞整份技能、模型表或历史消息。
- `subagent_fork` 只继承已完成轮次，**没有 provider / model / effort 覆盖**；换入口用新 `subagent`，`send_message` 不能换失败入口的模型。
- 重派前必读协议五：旧执行最终失败 / 已停止，**关联作业、文件改动与外部副作用均核对**。保留原任务、恢复点与验收，不盲目重放，不把新入口成功当验收成功。
- 团队换入口保留 task ID / DAG / 验收，换兼容 owner；暂存可改成员路由，运行时新建或复用替补成员后 `reassign_task`。受依赖阻塞的从未启动 pending 任务用 `edit_plan.update_task` 改 assignee。

## 四、输出上限与原会话续接

- 收到输出截断、`ran out of room before it finished` 或无 closing 的结束通知，**不能据此认定任务未做完、模型不可用或必须换人**。先核对任务状态及已有报告、日志、检查点；成果可能已完成，只差提交或回报。
- 原成员仍在册、会话已 inactive 且任务未终态时，优先向**原成员**发一次「继续」，让其从已有成果完成剩余提交；AgentTeams 用 `agent_teams_send_message`，普通可续接子代理用 `send_message`。已在运行则等待，不重复催促；保留有效 attempt，不为续接新建任务或重派，不重跑已完成的整套验证。
- **不要仅因输出上限调用 `remove_member`，也不要直接换模型。** 本次实测：移出团队后原会话会被标为 retired，续接报 `was retired and cannot be resumed`；此时再发「继续」不能恢复。运行时明确拒绝后停止重试，不手改 `.agent-teams/` 或伪称原会话恢复。
- 只有原会话确实无法续接或继续后仍有明确阻断，才按安全重派协议处理。已临近完成时，替补仅核对现有证据、补必要归属说明并提交，不从头重做；新会话必须明确标识为替补。用户指定保留原会话时，无法恢复先说明并取得替代方式确认。
- 报告写了 PASS 不等于任务已正式 completed；「继续」也不授权伪造通过。仍须核对实际产物、命令归属与当前 attempt，按原合同提交，后续独立质量门不省略。
